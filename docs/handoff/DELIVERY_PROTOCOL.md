# AIWorld 后续交付协议

更新日期：2026-09-11。

## 1. GitHub 是正式开发基线

私有仓库 `Crick-Latz/aiworld` 的 `main` 保存最近一次已验收版本。每项开发工作从 `main` 的明确 commit 建立 `work/<stage>` 分支，代码、测试和验证报告进入同一个 Pull Request。

源码 ZIP 与补丁退出常规交付流程。连接器或本地网络限制阻止正常提交时，才使用 bundle、源码包或补丁作为运输手段。运输文件不能替代仓库中的正常源码树。

## 2. 每轮交付记录

每轮开发回复应记录：

1. 输入基线 commit；
2. 工作分支和结束 commit；
3. Pull Request；
4. 实际修改范围；
5. 已运行的验收命令与结果；
6. 失败、未执行项和产品缺口；
7. 下一阶段建议。

每轮回复末尾保留“交给 Codex 的文件”栏目。常规 GitHub 交付写明无需文件；遇到 Windows 本地问题时，单独列出日志、指令或补丁。

## 3. 验收与证据

- 严格回归读取 `scripts/strict_suites.json`，断言数以当前 manifest 为准。
- 固定 seed 重放应记录 profile、seed、tick 数和诊断指纹。
- 自然实验的出现频率与结构性正确性分别记账。
- 修复后使用新的证据目录重跑，保留旧失败证据。
- 测试期间修改受指纹覆盖的源码会使该轮证据失效。

禁止通过删减断言、屏蔽异常、挑选有利 seed、增减资源或改变接受阈值制造通过结果。

## 4. 安全与清洁

仓库排除：

- `.git` 运输副本、`.tmp`、Godot `.godot` 缓存；
- Godot 引擎和本机工具二进制；
- `node_modules`、Python 缓存及可重建依赖；
- `.env*`、`*.local.*`、密钥、令牌和凭据；
- 大型运行日志与临时验收输出。

配置模板和 `.env.example` 可以入库。真实凭据保存在本机或 GitHub Secrets。疑似凭据进入待提交区时立即停止提交并报告文件路径。

## 5. 本地 Codex 的角色

Codex 主要处理 Windows 环境复现、本机 Godot 编辑器问题和用户明确要求的独立复核。常规源码整合由 GitHub 分支和 Pull Request 完成。Codex 做出本地兼容修复后，应提交到对应分支，或提供明确 diff 与验收报告供合并。
