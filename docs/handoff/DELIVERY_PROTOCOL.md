# AIWorld 后续交付协议

更新日期：2026-09-10

## 1. 每轮回复必须列出交给 Codex 的文件

每轮开发回复末尾单独设置“交给 Codex 的文件”栏目，并逐项列出：

- 实际生成且能够获取的文件；
- 文件用途；
- 是否为继续开发的必需输入；
- 推荐整合方式（完整源码、增量补丁或仅供审计）。

纯讨论回合必须明确写明“本轮无新增代码文件”，不得把历史产物重新标成新版本。

## 2. 交接说明的最低内容

每轮交接说明至少包含：

1. 输入源码基线及可核对的提交或源码指纹；
2. 本轮改动范围和明确排除的工作；
3. 推荐整合顺序，以及源码包与补丁是否二选一；
4. 所需环境版本与可直接执行的验收命令；
5. 本轮实际执行结果，不得以历史结果代替；
6. 失败、未执行项、已知缺口和未验证风险；
7. 下一阶段建议，但不得在未授权时顺手跨入下一阶段。

## 3. 源码与补丁

- 涉及源码改动时必须提供目标源码快照。
- 只有在基线明确且补丁经过可应用性检查时，才额外提供增量补丁。
- 完整源码与补丁描述同一批改动时只能选择一条整合路径，另一份仅用于对照。
- 补丁不适用、基线不一致或某项测试未运行时必须明确标注，禁止静默覆盖或假报通过。
- 下一轮以用户回传的本地整合结果为真实基线，先比较差异，再继续开发，避免从旧压缩包覆盖本地修复。

## 4. 验收与证据

- 日志、汇总、源码指纹和测试数量按本轮实际产出提供。
- 严格区分：通过、失败、因环境未执行、因前置失败中止。
- 不得通过删减断言、屏蔽异常、修改固定 seed、增减资源或改变接受阈值来制造通过结果。
- 失败后的修复必须使用新的证据目录重跑；旧失败证据保留用于审计。

## 5. 安全与清洁

交付源码包必须排除：

- `.git`、`.tmp`、Godot `.godot` 缓存；
- 引擎二进制和本机工具副本；
- `node_modules`、Python 缓存及其他可重建依赖；
- `*.local.*`、密钥、令牌、凭据和仅适用于本机的私有配置；
- 验收日志和运行输出（应放在独立证据包中）。

删除临时材料前应确认绝对路径位于预期临时目录。不得用强制覆盖、`git reset --hard` 或无审查清理解决冲突。
