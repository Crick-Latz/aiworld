# AIWorld 项目路线图

更新：2026-09-11。当前阶段：P7.0 信息子目标。

## 目标与优先级

世界依据真实状态持续演化。角色从自己的观察、关系和记忆出发形成计划，行动后果进入事件记录，并影响之后的选择。叙事层负责呈现可以追溯的因果。

当前优先完成运行框架。UI 与美术在自主信息搜索、社会委托及持续运行可靠性达到验收条件之后启动。玩家进入世界与大规模势力模拟继续保留为后续扩展。

```text
World State
    → Perception / Belief
    → Problem / PlanProposal
    → Subjective Adoption / Commitment
    → Step Selection / Rule Execution
    → Event Evidence / Memory Update
    → Reconsideration / Narrative
```

LLM 可参与世界输入编译、离线案例抽取和语言表达。在线提出的建议必须经过结构化边界。世界事实、资源变更、行动合法性与结果结算继续由模拟器负责。

## 当前实测结果

P7.0 保持固定地图、角色、资源参数、seed 61000 至 61009 和每组 1000 tick。framework 与 information 两组的唯一配置差异是 `information_subgoals`。信息组共创建 47 个来源子目标，完成 15 次搜索，其中 1 次通过当前感知找到来源；2 个信息目标得到解决，1 个对应父计划随后启动。10 个 seed 中 9 个出现行为分叉，第一组 treatment 完成同输入重放。

自然样本没有出现询问行为，完整 `ACQUIRE → CRAFT → MAIN` 计划链仍为零。受控测试已经覆盖有证据的询问对象、分享、拒绝、过期消息、错误报告复核和父计划恢复。当前产品缺口转向两个方向：提高社会知识证据在自然运行中的可达性，以及让已知材料缺口进入真实请求与协商。

这些数字属于机制观察。实验没有更换 seed、增加资源、放宽 timeout 或加入固定奖励。

## P7.0：信息缺口成为可执行子目标

规划器产生 `UNKNOWN_SOURCE(item)` blocker 后，`InformationSubgoalTracker` 从角色当前需求、候选计划和主观上下文建立 `FIND_SOURCE` 目标。角色可以沿自己的空间信念边界进行搜索，也可以在 ToM 中存在知情证据时询问当前可见对象。

```text
A 想捕鱼
    → A 知道鱼叉配方
    → A 缺贝壳且不知道来源
    → 形成 FIND_SOURCE(shells)
    → 选择主观搜索，或询问 A 认为知情的 B
    → 得到观察或回答事件
    → 更新 A 的空间信念
    → 原计划根据新上下文重新验证
```

回答由 B 自己的空间信念产生，并携带观察时间、接收时间、置信度、来源角色和事件号。较旧报告不能覆盖更新的亲眼观察；角色抵达报告地点后，感知层可以确认或推翻它。信息交换使用独立的 namespace RNG，不消耗天气、捕鱼等世界随机序列。

目标状态、尝试、搜索位置、被询问角色、拒绝和证据引用进入追加式 trace。目标解决本身不转移物品，也不伪造父计划完成。信息功能放在独立 `information` profile 中，既有 `framework` 行为轨迹保持兼容。

P7.0 的结构验收已经建立。自然实验暴露的零询问与零完整制作链保留为后续输入。

## P7.1：材料请求、协商与父计划恢复

利用已有 SocialSystem，把缺口转成可被接受或拒绝的请求。先接一种材料，保留原有 food/water/tool 行为的回归。

A 请求材料时，B 根据自己的库存、需求、关系与承诺评估。物品实际转移产生事件证据后，子目标才完成。A 的父计划重新构建并继续制作；失败或拒绝会使 A 改选办法。求助对象来自 A 的认知，不从全体角色真实库存中筛选最优答案。

每个请求都要拥有明确身份，并关联父计划、执行尝试与结果事件。重复通知、旧请求完成、其他角色得到材料等情况不得推进错误的计划。

## P7.2：承诺后果与自主委托故事

协商可以产生带条件的承诺。成功、违约与误解要进入角色的关系和记忆，改变下一次合作的概率。

最小产品验收是一条由 3-6 个角色自主推动的因果链：缺口出现，角色寻求帮助，协商改变条件，资源发生转移，父计划执行，随后履约或违约并影响后续关系。由规则与决策产生实际变化，观察层再将其命名为“委托”。

同时保留失败时间线。统一指标关注合法性、信息来源、可追溯性、重放，以及自主变化的覆盖度。减少无意义重复并增加可解释分叉，比增加 NPC 数量更优先。

## 小说认知支线：P6.N0 → N1 → N2

历史 P6.0 的文学行为模式文档属于设计先验。本轮 N0 建立逐条证据和检索接口，已经可以校验人工审核案例。

P7.0 已满足第一条信息闭环的进入条件。N1 位于 UI 与美术阶段之前，计划在 P7.1 材料请求闭环完成后启动真实文本导入，使案例评估可以覆盖搜索、询问、请求和协商。届时通过离线抽取、审核与反事实评估形成案例库，运行中先做 SHADOW 检索，验证角色知情边界及候选合法性。

N2 再评估将案例用于候选排序的有界先验。微调属于可选路线，以数据质量和评估结果为启动条件。案例中的剧情、叙述者知识与人物经历不能直接成为当前世界的事实或 NPC 自传记忆。

当前支持的三个问题类型是 HUNGER、THIRST、ISOLATION。政治或权力继承类案例需要先扩展可执行世界语义，再作为有效运行策略接入。详见 `docs/NOVEL_COGNITION.md`。

## RUNTIME-R1：持续运行可靠性

在扩展 UI 前，补齐完整 IslandSimulation checkpoint 与恢复。checkpoint 需要保存随机流、行动进度、计划承诺及认知对象，并检验恢复后与不中断运行相同。现有诊断 hash 和观察快照分别用于校验与显示，均不充当完整恢复文件。

随后处理事件归档、可追溯记忆压缩及长时间运行边界。原始事件引用应在摘要之后仍能定位，存储损坏、版本不匹配和重复恢复要能失败退出并说明原因。当前 prototype 使用单进程时钟，还需在持久化层建立这些保证。

## UI 与美术启动条件

完成 P7 核心因果链与 RUNTIME-R1 后，再设计观察体验。第一轮 UI 应能查看“发生了什么、这个角色当时知道什么、为何采纳或放弃计划、行动后果如何改变关系”。美术服务于这些观察任务，优先保持可读性。

当前仅把原观察入口接到统一运行配置，视觉表现保持原样。

## P8 以后：势力世界与历史分叉

在上述基础上扩展职位、领地、命令链及信息传播，形成权力接替与联盟变化。董卓提前死亡应由客观死亡事件及差异化知情时间引发计划重估，旧目标因前提失效而结束；系统继续根据新的利益关系生成行动。

这些机制需要多方资源和信息模型共同支撑。当前荒岛原型尚未实现完整三国政治模拟。
