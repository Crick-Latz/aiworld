本报告是观察结果，不代表 P6.3B-2 通用子目标已经实现。

## 结论先行

执行生命周期在本次检查中没有发现计数/事件引用错误，但**尚未观察到新增执行开关带来的行为改善**。
10 对运行的逐 tick scoped digest 都没有出现差异，最终全事件日志 SHA-256 也逐对相同。
不可把“受控鱼叉链跑通”扩写成“自然世界已经普遍会规划制作”。

本轮没有修改 production `game/src/`、资源数量/位置算法、效用、人格、超时默认值或美术 UI。
仅新增配对观察脚本、原始结果、报告，并在模块文档登记测试入口。

## 固定设计

- 预先固定种子 `61000..61009`，每组每种子 1,000 tick，三名原有角色，各出生于一个既有 POI。
- 同一个已生成的地形。种子改变资源位置与模拟 RNG，**不是十张不同地貌地图的测试**。
- 原始场景 `deserted_island_v2.json` 的人格、经历、库存；不注入知识、材料、现成庇护所，不移除竞争资源。
- 两侧均为 `LIVE_BRIDGE`；唯一配置差别为 `agency_plan_execution_enabled=false/true`。默认 timeout=16。
- 每对初始 world canonical 与 scoped digest 相等；两侧交错 step。
- 固定第一种子 61000 再运行一次 enabled：全事件 SHA、全 execution trace SHA、最终 scoped digest 一致。
- 数据：`game/docs/validation/data/p6_3b_1_natural_pilot.json`，27,166 bytes；包含逐种子结果、输入/源码指纹、引擎版本和三个完成案例的事件序号。

## 证据强度和限制

1. 全事件日志相等比原 AgencyMeasure 的尾部事件摘要更强，但仍不是所有内部状态逐位相等；digest 排除字段以 AgencyMeasure 注释为准。
2. replay 只覆盖预先选定的 61000，不声称十个种子全部重复运行。
3. 10 个种子、单一固定地形，不证明全地貌、长寿命存档恢复或任意多人配置的鲁棒性。
4. 无违反项只表示本脚本检查了的约束通过：run 计数、重复 step、来源事件存在且属于该 actor、来源非未来等，不证明没有其他漏洞。
5. 目前数据没有计量意图坚持早退比例、候选挤位率和超时前的逐次选择原因。不得把“效用黑洞”直接写成已实证唯一根因。

## 下一步：有界执行阻断诊断，不加新玩法

优先级现在应是“解释为何执行很少发生”，而非更多配方或增大浆果供给。
下一轮固定重放本样本中的 61000 与 61009（明确属于事后定位样本，不作总体频率推断），仅加只读观察：

1. 按真实决策边界区分 fresh softmax 与 intention early-return；不要用旧 trace 冒充当次决策。
2. 记录步骤候选是否已经在考虑集、是否挤入、被其他哪种行动击败；保留原 utility 与 trace 引用。
3. 对超时前最后数次决策保留 run/step/attempt/决策 tick，区分未选中、执行失败、主观来源失效和等待中的截尾情况。
4. 对 61009 的自然 crafted 找前后相邻的计划状态，用真实事件 seq 解释为何它没有归到 CRAFT 步骤；不根据时间接近编造因果。
5. 只有证据定位到具体接线 bug 时修 bug。若涉及意图/效用策略，先明确当前机制、替代方案及开关对照；不强制 NPC 完成计划，不直接给步骤加分来美化报告。
